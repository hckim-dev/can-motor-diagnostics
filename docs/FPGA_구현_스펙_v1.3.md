# CAN DO FPGA 구현 스펙

문서 버전 v1.3 · 개정일 2026년 11월 19일 · FPGA 담당 현수근

Basys3에서 엔코더 A/B를 생성하고, STM32의 진단 응답을 같은 FPGA 시계로 측정한다. Jetson은 계측값과 CAN 보고를 같은 회차로 연결한다. 본문은 RTL 구현과 통합 수락 기준을 다루며, 전동 시트 모터 시험과 지그 제작은 15절에 정리한다.

## 1 적용 기준과 담당 범위

**설계 기준**은 원문에 정의된 동작과 전송 형식이다. **초기값**은 실측 후 조정할 수 있는 파라미터다. **구현 제안**은 이 문서에서 구체화한 내부 처리 방식이며 관련 담당자와 검토한 뒤 구현 기준에 반영한다. **현물 확인**은 핀·배선·전기 조건을 실제 보드에서 대조할 항목이다.

| 항목 | 적용 기준 |
|---|---|
| 시험 플랫폼 | Digilent Basys3, 100 MHz 시스템 클록 기준 |
| 주 출력 | 3.3V 엔코더 A/B 2채널, 74HC157을 거쳐 모터 STM32 TIM4에 입력 |
| 관측 입력 | TEST_READY, DIAG_FAULT 각 1비트 |
| 계측 및 전송 | 1 MHz 타임스탬프, 내장 USB-UART, 115200 baud·8N1 |

Qt가 제어를 요청하고 Jetson이 CAN 명령과 허가를 송신한다. 모터 STM32는 실행과 진단을 담당한다. FPGA는 로컬 버튼으로 시험을 시작하고, Jetson은 FPGA·CAN 기록을 대조해 판정한다.

## 2 외부 인터페이스와 배선

| 논리 신호 | 방향 | Basys3 연결 | 상대 연결 | 기준 |
|---|---|---|---|---|
| enc_a | 출력 | JA1 / J1 | 1 kΩ → MUX 3번, MUX 4번 → PB6 | LVCMOS33 |
| enc_b | 출력 | JA2 / L2 | 1 kΩ → MUX 6번, MUX 7번 → PB7 | LVCMOS33 |
| test_ready | 입력 | JB1 / A14 후보 | 모터 PC0 / CN7-38 후보 | 핀·헤더 도통 확인 |
| diag_fault | 입력 | JB2 / A16 후보 | 모터 PC1 / CN7-36 후보 | 핀·헤더 도통 확인 |
| uart_tx | 출력 | A18, 내장 USB-UART 송신 핀 | 보드 USB → Jetson USB | 실물 리비전 대조 |
| clk_100m | 입력 | W5 | 보드 클록 | 주기 10 ns |
| signal_gnd | 기준 | JA5 등 Pmod GND | 모터 보드 공통 GND | 신호 기준 전위 |

출처는 S1 B.3·B.7과 S4다. PC0/PC1의 실제 헤더 연결과 기존 I²C·GPIO 점유를 CubeMX, 보드 리비전, 도통 측정으로 확인한다. 후보 핀의 검증 결과를 XDC와 MCU 핀 표에 함께 반영한다.

MUX는 3.3V로 구동하며 선택 LOW는 REAL, HIGH는 TEST다. /G는 LOW다. 실제 엔코더 A/B는 레벨 변환 후 MUX 2·5번으로 들어가고, FPGA는 3·6번으로 들어간다. 시험 입력에는 원문 기준의 10 kΩ 풀다운을 적용한다. Pmod 전원핀과 다른 보드의 전원 연결은 원문 전원 배선 기준을 따른다.

### 신호 의미

- TEST_READY는 모터 MCU의 TEST_ARMED 또는 TEST_ACTIVE에서 HIGH다. 다른 상태에서는 LOW다.
- DIAG_FAULT는 fault_mask가 0이 아니면 HIGH이며, 명시 RESET으로 고장이 해제되면 LOW다. 원인 구분은 Jetson이 CAN 고장 비트로 확인한다.
- USB-UART는 FPGA에서 Jetson으로 시험 정보를 전송한다. 시험 준비·정지·리셋은 Qt → Jetson → 모터 STM32 경로로 요청한다.
- TEST 모드의 모터 공급 OFF·PWM LOW 확인은 MCU와 지그의 준비 조건이다. FPGA는 TEST_READY로 준비 허가를 받는다.

### 보드 로컬 조작 구현 제안

시나리오는 SW[1:0]의 01·10·11을 각각 NORMAL·NO_EDGE·GAP_500에 배정하고 00에서는 대기한다. 시작은 btnC, FPGA 로컬 리셋은 btnD를 후보로 둔다. btnC·btnD의 S4 후보 핀은 U18·U17이다. 버튼은 동기화·20 ms 안정 확인·새 눌림 검출을 거친다. 버튼 배정과 디바운스 시간은 구현 제안이다.

MCU의 고장 RESET과 FPGA 로컬 리셋은 별도 동작이다. 실행 중 FPGA 로컬 리셋은 세션 초기화로 처리하고 Jetson은 진행 회차를 판정 불가로 닫는다.

## 3 정상 A와 B 파형

**초기값은 각 채널 20 cycle/s, 위상차 90°이며, 균등한 4상 전이로 생성한다.** 각 상태를 12.5 ms 유지하면 A와 B 각각의 주기는 50 ms, 듀티는 50%가 된다. 기준 순서는 아래와 같고 MCU의 정방향 계수 부호와 대조한다.

| 정상 재생 경과 | A | B | 전이 |
|---|---|---|---|
| 0 ms | 0 | 0 | 시작 상태 |
| 12.5 ms | 0 | 1 | B 상승 |
| 25 ms | 1 | 1 | A 상승 |
| 37.5 ms | 1 | 0 | B 하강 |
| 50 ms | 0 | 0 | A 하강, 다음 주기 시작 |

상태 순서는 `{A,B} = 00 → 01 → 11 → 10 → 00`이다. 한 번에 한 비트만 바꾸고 A/B 출력은 레지스터에서 갱신한다. 100 MHz 클록에서는 1,250,000클록마다 상태를 한 단계 진행한다. 동작은 시스템 클록과 clock enable로 구성하는 방식을 제안한다.

| 구분 | 20 cycle/s일 때 |
|---|---|
| 채널 A 주기 / HIGH 유지 | 50 ms / 25 ms |
| 채널 B 주기 / HIGH 유지 | 50 ms / 25 ms |
| A/B 상태 전이 간격 | 12.5 ms |
| x4 계수 속도 | 80 count/s |
| 100 ms 기대 카운트 | 정방향 약 8 count |

### MCU가 확인할 baseline

FPGA는 정상 파형을 1초 출력한다. MCU는 ARM_TEST 수락 후 5초 안에 정상 전이의 500 ms 연속 확인을 완료해야 한다. 그 500 ms 동안 매 100 ms 구간의 정방향 카운트는 초기 기준 6~10 count이며 반대방향 전이 또는 연속 100 ms 무변화가 없어야 한다.

5초는 ARM_TEST 수락부터 세는 MCU의 준비 마감이다. FPGA 시작부터 세는 1초 baseline과 구분한다. ARM 수락 4.8초 뒤에 파형을 시작하면 연속 확인에 필요한 시간이 부족하다. 통합 조작은 READY 확인 후 지체 없이 시작하도록 한다.

RPM 표시는 출력축 1회전당 x4 유효 카운트 C를 실측한 뒤 환산한다. 80 count/s의 시험 입력은 4,800/C RPM에 대응한다. C 확정 전에는 cycle/s와 count/s를 시험 기준으로 사용한다.

## 4 고정 펄스 시험 시나리오와 파형 경계

세 시험 모두 FPGA 시작 버튼이 수락된 시점부터 1초간 정상 A/B를 출력한다. 아래 그림의 시간은 그 시점부터 센 경과 시간이다. MCU는 이 구간에서 펄스를 계수해 TEST_ACTIVE로 전환한다. FPGA는 1,000 ms에 INJECT를 기록하고 시나리오별 관측을 시작한다.

| 시나리오 | FPGA A/B 동작 | END 시각 | MCU에서 확인할 결과 |
|---|---|---|---|
| 1 NORMAL | 정상 출력 계속 | 3,000 ms | TEST_ACTIVE 유지, CAN fault_mask=0, DIAG=0 |
| 2 NO_EDGE | 1,000 ms부터 현재 레벨 고정 | 2,000 ms | FEEDBACK_MISSING, FAULT, DIAG 상승 |
| 3 GAP_500 | 1,000 ms부터 고정, 1,500 ms에 정상 전이 재개 | 2,000 ms | 누락 고장 보고, 복귀 후에도 RESET 전까지 고장 유지 |

### 4.1 NORMAL 정상 파형 유지

![그림 4-1 NORMAL의 관측 시작 전후 A/B 파형](assets/fpga_spec_v1.1/normal.png)

FPGA는 A/B를 00에서 시작해 12.5 ms마다 한 비트씩 바꾼다. 그림에서 987.5 ms에는 B가 내려가며 11에서 10으로 바뀌고, 1,000 ms에는 A가 내려가며 10에서 00으로 바뀐다. NORMAL의 INJECT는 이 시점부터 관측을 시작했다는 표시다. 파형은 같은 간격으로 계속 진행한다.

1,000~3,000 ms의 2초 동안 MCU는 TEST_ACTIVE를 유지하고 DIAG와 CAN 고장 비트는 0이어야 한다. 3,000 ms에 END를 보내고도 펄스를 유지한다. STOP으로 READY가 내려가면 idle로 복귀한다.

<!-- pagebreak -->

### 4.2 NO_EDGE 현재 레벨 고정

1,000 ms에 파형 진행을 멈추고 A/B의 현재 값을 유지한다. MCU에는 마지막 정상 전이 이후 새 에지가 들어오지 않는다. 그림은 주입 경계를 확대해 보여준다. 고정 상태는 관측 마감인 2,000 ms까지 이어진다.

![그림 4-2 NO_EDGE의 주입 경계와 A/B 고정](assets/fpga_spec_v1.1/no_edge.png)

| FPGA 경과 시간 | A/B | 처리 |
|---|---|---|
| 987.5 ms | 11 → 10 | baseline의 마지막 정상 전이. B 하강 |
| 1,000 ms | 10 유지 | 예정된 A 하강을 생략. 고정 시작 시각 t0를 INJECT에 기록 |
| 1,000~2,000 ms | 10 유지 | MCU의 DIAG 상승을 관측. 첫 상승 시각 t1과 t1-t0를 DIAG_EDGE에 기록 |
| 2,000 ms | 관측 완료 | END 전송. 이후 출력 처리는 13절 참조 |

**10이 유지되는 이유**는 이 예에서 t0 직전 A가 HIGH, B가 LOW이기 때문이다. 고장 주입 시 레지스터 값을 유지하므로 t0에 새 에지가 생기지 않는다. 현재 값이 11인 조건에서는 A와 B가 모두 HIGH로 유지된다.

**MCU와 FPGA는 서로 다른 시점에서 시간을 센다.** MCU의 초기 누락 기준은 마지막 count 변화 후 200 ms다. 그림의 마지막 에지인 987.5 ms를 기준으로 하면 산술상 1,187.5 ms에 기준에 도달한다. 실제 DIAG 상승은 MCU의 진단 주기와 출력 지연을 포함한다. FPGA는 t0인 1,000 ms부터 DIAG 상승을 측정하며, Jetson은 초기 허용값 300 ms 이내인지 CAN의 FEEDBACK_MISSING 및 FAULT와 함께 확인한다.

### 4.3 GAP_500 고정 후 정상 복귀

NO_EDGE와 같은 방식으로 A/B를 고정하고, 500 ms 뒤에 멈췄던 상태의 다음 상태로 진행한다. 그림은 주입과 복귀 경계만 확대했다. 가운데 생략 구간에서도 A는 HIGH, B는 LOW를 유지한다.

![그림 4-3 GAP_500의 주입 및 복귀 경계](assets/fpga_spec_v1.1/gap_500.png)

| FPGA 경과 시간 | A/B | 처리 |
|---|---|---|
| 987.5 ms | 11 → 10 | 마지막 정상 전이 |
| 1,000 ms | 10 유지 | 고정 시작 t0 기록 |
| 1,500 ms | 10 → 00 | A 하강으로 정상 순서 재개 |
| 1,512.5 ms | 00 → 01 | B 상승. 이후 12.5 ms마다 계속 진행 |
| 2,000 ms | 관측 완료 | END 전송. 이후 출력 처리는 13절 참조 |

**500 ms는 고정 명령 구간**인 1,000~1,500 ms다. **MCU 입력의 에지 간격은 512.5 ms**로, 987.5 ms의 마지막 에지부터 1,500 ms의 복귀 에지까지다. 이 수치는 정상 전이와 고정 명령이 같은 클록에 예정될 때 고정을 우선하는 v1.0 구현 제안에 따른다. 이 제안의 t0·복귀 규칙은 FPGA와 MCU 담당자가 같은 기준으로 확인한다.

펄스가 복귀해도 MCU는 RESET 전까지 고장 래치를 유지해야 한다. DIAG 상승과 함께 READY가 내려가도 FPGA는 예정된 복귀 전이를 출력하고 2,000 ms에 END를 전송한다. 처음 연동할 때는 로직 분석기로 MCU의 PB6/PB7과 DIAG를 캡처하고, 에지 간격과 UART의 INJECT·DIAG_EDGE·END 기록을 비교한다.

## 5 시험 제어 상태와 중단 처리

FPGA 내부 상태는 구현 제안이다. UART phase는 원문의 0 idle, 1 baseline, 2 observe, 3 completed를 유지한다.

| 내부 상태 | 진입과 처리 | 출력 / UART phase |
|---|---|---|
| IDLE | 초기화 후 대기, READY·DIAG·새 시작 확인 | A/B 초기값 00 제안 / 0 |
| BASELINE | 시나리오 고정, run_seq 증가, BASELINE_START 기록 | 정상 A/B 1초 / 1 |
| OBSERVE | t0 캡처, INJECT, 시나리오 실행·DIAG 관측 | 시나리오 파형 / 2 |
| COMPLETED | 관측 마감에 END, 정상 시나리오 출력 유지 | 완료 후 정책 / 3 |
| ABORTED_HOLD | 실행 중단에 ABORT, 재시작 조건 대기 | idle 전환 제안 / 3 제안 |
| INVALID_HOLD | overflow 또는 로컬 무효 상태 래치 | 새 실행 억제, STATUS b3 |

시작 시 READY=1, DIAG=0, 유효한 시나리오, 새 버튼 눌림, 기존 실행 없음, overflow 없음을 확인한다. baseline/observe 중 시작 버튼은 현재 실행을 바꾸지 않는다. 시나리오 선택은 BASELINE_START에서 고정하며 실행 중 스위치 변경은 다음 회차에 적용한다.

### READY 하강과 DIAG 상승의 우선순위

1. 동기화된 DIAG 상승 시각을 먼저 캡처한다. 주입 후 첫 상승이면 t1과 latency를 저장한다.
2. READY 하강 시 DIAG가 아직 보이지 않으면 2 ms 유예하여 두 입력의 관측 순서 차이를 흡수한다.
3. 고장 시나리오에서 주입 후 DIAG 상승이 확인되면 시나리오·관측·END까지 진행한다. 고장 원인은 Jetson이 CAN으로 대조한다.
4. 유예가 끝나도 DIAG가 없으면 ABORT를 전송한다. Jetson은 STOP·EStop·모드 변경 근거가 있으면 ABORTED, 재부팅·단절·원인 불명이면 INCONCLUSIVE로 처리한다.

2 ms 유예는 300 ms 응답 기준을 늘리는 시간이 아니다. DIAG의 실제 관측 시각을 그대로 보존한다. 유예 중 출력 처리 방식과 baseline·NORMAL에서 예상 밖 DIAG 처리 방식은 13절의 구현 제안을 따른다.

### 다음 실행 수락

END 후 READY=0을 관측한 뒤 재상승하고, 버튼 해제 후 새 눌림이 있어야 다음 실행을 수락한다. 고장으로 이미 READY가 내려갔던 경우도 관측 완료와 다음 ARM을 구분한다. FPGA 리셋·overflow 해제 후에도 현재 READY가 HIGH라는 이유만으로 시작하지 않도록 새 준비 절차를 확인한다.

시험 도중 MCU RESET이나 STOP이 고장과 겹치면 FPGA의 두 GPIO만으로 원인을 모두 식별하기 어렵다. Jetson은 CAN 상태·명령 근거를 함께 사용하여 회차를 종료한다.

## 6 시간 계측과 입력 동기화

| 항목 | 요구 또는 초기값 |
|---|---|
| fpga_tick_us | 부팅 후 1 MHz u32 자유 실행 카운터 |
| baseline 시작 | 실제 정상 파형 실행 시작과 같은 제어 시점에 기록 |
| t0 | 실제 고정 동작이 시작되는 FPGA 제어 시점 |
| t1 | 동기화된 DIAG_FAULT의 주입 후 첫 상승 |
| latency_us | u32 모듈러 차분 t1-t0 |
| 누락 검출 초기값 | MCU의 마지막 count 변화 후 200,000 µs |
| GPIO 응답 허용 초기값 | t0부터 t1까지 300,000 µs 이내 |
| GPIO 순서 유예 | READY 하강 후 최대 2,000 µs |
| 실행 길이 | 60초 미만 |

1 MHz 카운터는 약 71분 35초마다 wrap된다. 단일 시험의 시간 차분은 u32 모듈러 연산으로 계산한다. 카운터 wrap을 FPGA 재부팅으로 오인하지 않도록 Jetson과 검증한다. 비정상 초기화·순번 역행이나 재부팅 여부가 모호한 경우 새 세션으로 처리한다.

타임스탬프는 이벤트가 발생한 순간 레지스터에 저장한다. FIFO 대기 시간과 UART 송신 시작 시각이 계측값을 바꾸지 않도록 한다. UART 도착 시각과 CAN 도착 시각의 차이는 통신 지연을 포함하므로 FPGA 지연과 별도로 기록한다.

### 입력 처리 구현 제안

TEST_READY·DIAG_FAULT는 각각 시스템 클록 도메인으로 2단 동기화한 후 사용하고, 동기화 레지스터에 ASYNC_REG 속성을 적용한다. 버튼과 스위치도 동기화하되 DIAG 관측에는 버튼용 20 ms 디바운스를 적용하지 않는다. MCU GPIO의 부팅·리셋 LOW와 입력 풀다운을 확인한다.

100 MHz 분주에서 100클록마다 1 µs clock enable을 생성한다. 1 µs는 타임스탬프의 단위다. 입력 동기화 지연, 클록 오차, MUX·배선 지연을 포함한 실제 계측 오차는 초기 지그 검증에서 측정한다.

### timing_valid

NO_EDGE/GAP_500에서 유효한 주입 이후 첫 DIAG 상승이 캡처되면 시간값을 유효하게 보고한다. baseline 중 고장, GPIO 검증 부족, overflow 등 계측 전제 불성립은 유효 시간 근거로 사용하지 않는다. GPIO의 실물 검증 상태는 Jetson 설정·manifest에도 기록한다.

정상 관측 완료까지 DIAG가 없으면 END의 timing_valid=0이다. NORMAL의 latency와 limit는 Jetson 결과에서 null이다. NO_EDGE/GAP_500은 관측·통신·GPIO가 모두 유효했다면 응답 없음 FAIL로 판정할 수 있다.

## 7 USB UART 프레임 규격

설계 기준은 FPGA wire protocol 1.0, 115200 baud, 8N1, 고정 22 byte, little-endian이다. 보드의 내장 USB-UART를 통해 Jetson USB로 연결한다.

| Byte | 필드 | 형식과 의미 |
|---|---|---|
| 0~1 | sync | A5 5A |
| 2 | major | u8, 1 |
| 3 | type | u8, 1 STATUS / 2 BASELINE_START / 3 INJECT / 4 DIAG_EDGE / 5 END / 6 ABORT |
| 4~5 | tx_seq | u16, 모든 전송 프레임마다 증가 |
| 6~7 | run_seq | u16, 수락된 시험마다 증가 |
| 8 | scenario | u8, 0 idle / 1 NORMAL / 2 NO_EDGE / 3 GAP_500 |
| 9 | phase | u8, 0 idle / 1 baseline / 2 observe / 3 completed |
| 10~13 | fpga_tick_us | u32, FPGA 부팅 후 1 MHz 카운터 |
| 14~17 | value | u32, DIAG_EDGE에서 주입 후 latency_us, 나머지는 0 |
| 18~19 | flags | u16, b0 READY / b1 DIAG / b2 timing_valid / b3 overflow 또는 invalid, b4~15는 0 |
| 20~21 | crc | CRC-16/CCITT-FALSE, B2~B19 대상, CRC 하위 바이트 먼저 |

CRC는 poly=0x1021, init=0xFFFF, refin=false, refout=false, xorout=0이다. 각 입력 바이트는 MSB부터 처리한다. 검사 문자열 `123456789`의 CRC 결과는 0x29B1이다.

### 골든 벡터

```text
A5 5A 01 03 03 00 01 00 02 02 40 42 0F 00 00 00 00 00 01 00 9E B0
```

이 벡터는 INJECT, tx_seq=3, run_seq=1, scenario=2, phase=2, tick=1,000,000 µs, value=0, READY=1, CRC=0xB09E를 뜻한다. 인코더와 Jetson 디코더 양쪽에서 길이·필드·CRC가 동일해야 한다.

STATUS는 100 ms마다, 이벤트는 발생 즉시 전송 대기열에 넣는다. 22 byte를 8N1로 보내는 선로 시간은 약 1.91 ms다. 이벤트 시각은 프레임 대기 전에 캡처하고, 같은 시각의 이벤트에는 일정한 전송 순서를 적용한다.

tx_seq는 u16 모듈러 순번으로 다루고 run_seq는 65535 이후 동일 연결에서 0을 재사용하지 않는다. run_seq 소진 시 보드 재설정과 새 fpga_session으로 다시 준비한다. 최초 tx_seq 값은 13절의 협의 항목이다.

## 8 UART 이벤트와 전송 무결성

| 이벤트 | 발생 시점 | 이벤트 데이터 |
|---|---|---|
| STATUS | 100 ms마다 | 현재 phase·scenario·READY·DIAG·계측/오류 상태 |
| BASELINE_START | 새 실행 수락·파형 시작 | 새 run_seq, 고정된 scenario, 시작 tick |
| INJECT | 관측 시작. 고정형은 준비 종료, 실측형은 설정된 사전 재생 종료 | t0, observe 진입, value=0 |
| DIAG_EDGE | 주입 후 첫 DIAG 상승 | t1, latency_us, timing_valid |
| END | scenario 관측 구간 완료 | 완료 tick, 계측 유효성, 현재 관측 상태 |
| ABORT | 실행 중단 확정 | 중단 tick, 현재 관측 상태 |

STATUS는 대기 상태에서도 송신하여 Jetson이 새 실행 전 idle을 확인할 수 있게 한다. 이벤트는 실행 당시의 run_seq·scenario·phase·flags를 스냅샷으로 저장한다. 이미 큐에 넣은 이벤트가 나중 상태값으로 덮어써지지 않도록 한다.

### 큐와 overflow

pending 이벤트 FIFO 깊이는 16개다. FIFO가 가득 차면 overflow를 래치하고 STATUS b3으로 계속 보고한다. 로컬 리셋 전까지 다음 실행을 금지한다. 진행 중 회차의 증거가 손실되면 Jetson은 INCONCLUSIVE로 처리한다.

이벤트는 보존하고 STATUS의 미전송 중복 요청은 최신 상태로 합치는 방식을 구현 제안으로 둔다. tx_seq는 실제 프레임 송신 순서에서 부여한다. UART가 한 프레임을 보내는 동안에는 프레임을 완결하고 다음 프레임을 시작한다.

CRC 오류·순번 누락이 발생하면 Jetson은 sync를 다시 찾아 재동기화하고 진행 회차를 무효화한다. 이후 STATUS가 정상이어도 이미 빠진 시험 이벤트의 근거를 복원한 것으로 취급하지 않는다. 수신 STATUS 500 ms 공백도 진행 시험의 관측 단절로 처리한다.

### 세션

Jetson은 USB 연결마다 fpga_session UUID를 만들고 `(fpga_session, run_seq)`를 run_id로 사용한다. FPGA는 run_seq와 tx_seq 및 tick을 보낸다. UART의 phase에 새 내부 상태 번호를 임의 추가하지 않는다.

중간에 연결한 STATUS observe/completed만으로 시험 전체를 수락하지 않는다. 새 idle과 BASELINE_START부터 수집해야 한다. FPGA 리셋·연결 단절 뒤에는 새 준비와 새 시험 회차로 진행한다. 실행 중 MCU RESET의 세부 판정에는 CAN 명령·상태 근거를 사용한다.

## 9 Jetson 판정과 동일 회차 증거 연결

| 결과 | 적용 조건 |
|---|---|
| NORMAL PASS | 유효한 baseline과 전체 2초 관측, TEST_ACTIVE 유지, CAN fault_mask=0, DIAG=0, 기록 성공 |
| NO_EDGE PASS | 유효한 주입·1초 관측, 새 FEEDBACK_MISSING·FAULT·DIAG 상승, latency≤300,000 µs, 기록 성공 |
| GAP_500 PASS | NO_EDGE의 검출·시간 조건, 실제 A/B 복귀 및 관측 완료 END, END 이후 새 CAN 상태·고장에서 래치 유지 |
| FAIL | 시험·계측·통신이 유효한데 응답 없음, 틀린 고장, 정상 파형 오탐 또는 허용 시간 초과 |
| ABORTED | CAN 근거로 사용자 STOP·EStop·모드 변경·시험 중 RESET 확인 |
| INCONCLUSIVE | 시작·baseline·GPIO·세션·통신·로그 근거 부족, 원인 불명 또는 중간 접속 |

DIAG_FAULT는 모든 고장의 합성 신호다. 같은 회차에서 기대 고장 bit2 FEEDBACK_MISSING, 즉 0x0004와 FAULT 상태를 확인한다. 다른 새 고장 비트가 함께 발생하면 그 원인을 대조한다.

### 고장으로 epoch가 바뀌는 경우

첫 고장 래치로 모터의 제어 epoch가 바뀌어도 동일 motor_boot와 TEST 모드가 확인되면 진행 중 run_id를 유지한다. Jetson은 새 MOTOR_HELLO에서 epoch·boot를 확인하고 새 epoch의 MOTOR_STATE에서 TEST·FAULT, MOTOR_FAULT에서 새 FEEDBACK_MISSING을 대조한다. 여기에 같은 FPGA run의 INJECT·DIAG_EDGE·END를 연결한다.

관련 CAN ID는 MOTOR_HELLO 0x700, MOTOR_STATE 0x200, MOTOR_FAULT 0x090이다. STATE는 300 ms, FAULT는 1000 ms의 필드별 최신성 기준을 사용한다. 각 메시지의 freshness와 세션 확인을 통과한 근거를 사용한다.

### 마감과 저장

END 수신 후 최대 500 ms 동안 지연 CAN/UART 증거를 추가 수집한다. 이 기간은 test.status=RUNNING, reason=RESULT_PENDING으로 표시한다. 500 ms 수집 대기가 GPIO 응답 허용 300 ms를 바꾸지는 않는다.

GAP의 END 수신 후 500 ms 이내에 동일 MCU 부팅·TEST 회차의 새 MOTOR_STATE와 MOTOR_FAULT를 각각 확인한다. 유효한 새 보고에서 래치가 해제되면 FAIL, END 또는 새 보고가 빠지면 INCONCLUSIVE다.

최소 기록은 run_id, scenario_id, scenario_version, motor_boot, mode, 기대·관측 fault_mask, timing_source, latency_us, limit_us, result, reason, evidence_ids, 시작·종료 수신 시각이다. 고정형은 fpga-basic/1.0, 실측형은 15.3절을 적용한다.

원본 raw_fpga.jsonl·raw_can.jsonl과 events.jsonl을 연결하고 manifest.json에 FPGA build, XDC·설정 버전, GPIO 검증 여부를 남긴다. 저장 완료를 확인한 결과를 확정한다. 기능 관측 단계의 functional_only=true 설정은 GPIO 없는 시간 판정을 구분하는 데 사용한다.

## 10 RTL 구성과 파라미터

아래 모듈 경계는 구현 제안이다. 단일 100 MHz 클록에서 clock enable로 주기와 파형을 제어하고, UART 송신 상태가 파형·계측 진행을 지연시키지 않게 구성한다.

| 기능 | 처리 내용 | 주요 검증 |
|---|---|---|
| 입력·리셋 처리 | READY/DIAG 동기화, 버튼 디바운스, 새 눌림 | 부팅·버튼 유지·비동기 입력 |
| 시간 기준 | 1 µs tick, 12.5 ms 전이 허가 | 주기, wrap, 경계 클록 |
| A/B 생성 | 4상 상태, 고정·실측 간격, 유지·복귀 | 한 비트 전이, 정방향, 구간 경계 |
| 시나리오 제어 | baseline·observe·완료·중단, 재수락 | READY/DIAG 경합, 중복 시작 |
| 응답 캡처 | t0·첫 t1·latency·valid 저장 | 송신 대기와 무관한 시각 |
| 프레임·FIFO·CRC | 22 byte 구성, 순번, 이벤트 보존 | 골든 벡터, overflow |
| UART TX | 115200 8N1 직렬 송신 | 비트 시간, 프레임 연속성 |

| 파라미터 | 초기 설정 | 성격 |
|---|---|---|
| CLK_HZ / TICK_HZ | 100,000,000 / 1,000,000 | 보드 기준 / 원문 계측 단위 |
| AB_CYCLE_HZ / AB_STEP_US | 20 / 12,500 | 시험 초기값 / 파생값 |
| BASELINE_US | 1,000,000 | 원문 시나리오 |
| NORMAL_OBSERVE_US | 2,000,000 | 원문 시나리오 |
| FAULT_OBSERVE_US / GAP_US | 1,000,000 / 500,000 | 원문 시나리오 |
| READY_DIAG_GRACE_US | 2,000 | 원문 분류 유예 |
| STATUS_PERIOD_US | 100,000 | 원문 전송 주기 |
| EVENT_FIFO_DEPTH / UART_BAUD | 16 / 115200 | 원문 규격 |
| BUTTON_DEBOUNCE_US | 20,000 | 구현 제안 |

MCU의 200 ms 누락 검출, 500 ms 정상 확인, ARM 후 5초 마감은 MCU 설정이다. 300 ms PASS 한계와 END 후 500 ms 수집은 Jetson 판정 설정이다. 통합 manifest에서 각 설정의 소유자와 값을 함께 관리한다.

100 MHz를 정수 868클록/bit로 나누면 약 115207 baud가 되므로 이 분주를 구현 후보로 사용할 수 있다. 실제 baud 오차와 송신 파형을 측정한다. 1 µs tick을 단순 9분주하여 UART baud로 사용하면 오차가 커지므로 시스템 클록 기준으로 분주한다.

|---|---|---|

| V07 | DIAG 상승·READY 하강 순서 교환 | 2 ms 내 순서 차이에서도 첫 t1 보존, 기대 고장 시 END까지 진행 |
| V08 | READY 하강·DIAG 없음 | 유예 후 ABORT, CAN 근거에 따른 최종 원인 분류 |
| V09 | 응답 경계·없음 | 299,999·300,000·300,001 µs 캡처값 구분, 유효 관측의 무응답은 FAIL 가능 |
| V10 | baseline 고장·예상 밖 고장 | timing_valid와 CAN 원인 대조, 근거에 맞는 FAIL/INCONCLUSIVE |
| V11 | 연속 시작·스위치 변경 | 회차·시나리오 불변, READY 재상승과 새 버튼 전 재시작 없음 |
| V12 | UART·CRC | 22 byte 골든 벡터, 0x29B1 검사, 시각·순번·LE 배치 일치 |
| V13 | FIFO16 overflow·UART 단절 | b3 래치·다음 실행 억제, Jetson INCONCLUSIVE |
| V14 | tick/tx_seq wrap·run_seq 소진 | 모듈러 차분 정확, run_seq 0 재사용 방지 |
| V15 | FPGA 재부팅·중간 접속 | 새 세션, 이전 run 무효화, 새 idle·BASELINE부터 재수락 |
| V16 | 고장 시 epoch 갱신 | 동일 boot·TEST 확인 후 같은 run_id에 새 epoch CAN 증거 연결 |
| V17 | 지그 현물 검증 | MCU 입력 PB6/PB7과 DIAG 동시 캡처, UART t0/t1와 실제 파형 대조 |
| V18 | GPIO 미연결·한쪽 전원 OFF | 입력 부유·역급전 조건 점검, 검증 전제 부족 시험의 판정 불가 처리 |

V17은 FPGA 출력 핀뿐 아니라 MUX를 지난 MCU 입력에서도 확인한다. 채널 A/B의 주기·순서, 고정 시작, GAP 복귀, DIAG 상승, 시험 이벤트를 한 회차 증거로 저장한다. 반응 지연은 원본 파형에서 계산한 값과 UART latency_us를 비교한다.

## 14 후속 시험용 에지 및 전압 이상 주입

기본 3개 시나리오를 검증한 뒤, 에지 간격 증가·에지 누락·느린 전이·전압 레벨 미달·Hi-Z를 시험 후보로 적용한다. TEST에서 모터 공급 OFF와 PWM LOW를 확인한다. 정상 A/B로 TEST_ACTIVE에 진입한 뒤 한 종류의 이상을 주입한다. 한 채널만 바꾸는 시험은 A부터 시작하고 B는 정상 출력을 유지한다.

| 시험 후보 | 바꾸는 물리량 | 재현 수단 |
|---|---|---|
| 에지 간격 증가 | 다음 전이까지 유지하는 시간 | FPGA의 A/B 상태 갱신 시각 |
| 에지 누락·짧은 펄스 | 예정된 전이 또는 펄스 폭 | FPGA 전이 보류 또는 별도 시험 패턴 |
| 느린 상승·하강 | 전압이 올라가거나 내려가는 시간 | 가변 에지 신호 발생기 또는 외부 지그 |
| HIGH 저하·LOW 상승 | HIGH 또는 LOW 구간의 실제 전압 | 가변 진폭·오프셋 발생기 또는 DAC |
| Hi-Z · 단선 모사 | FPGA 출력의 구동 여부 | FPGA OBUFT 또는 외부 아날로그 스위치 |

### 14.1 에지 간격 증가와 누락

**간격 증가**는 출력 레벨을 유지하는 시간을 늘리는 경우다. 00 → 01 → 11 → 10의 순서는 유지하고 상태 간격만 바꾼다. 정상 20 Hz에서는 각 상태를 12.5 ms 유지한다. 예를 들어 상태 하나를 25 ms 유지하면 다음 에지가 12.5 ms 늦어진다. 네 상태를 모두 25 ms씩 유지하면 채널당 10 Hz, 위상차 90°다. 정상 속도로 복귀하면 다음 유효 상태부터 12.5 ms 간격으로 진행한다.

**에지 누락**은 지정 구간 동안 현재 상태를 유지하고 예정된 전이를 보류해 재현한다. 지연이 끝나면 다음 유효 상태부터 진행해 두 비트가 동시에 바뀌는 전이를 피한다. 한 채널의 짧은 펄스를 MCU가 놓치는 조건은 펄스 폭을 줄인 별도 패턴으로 시험한다. 실제 TIM4 입력 필터 설정에서 펄스 폭을 단계적으로 바꾸며 통과·미검출 경계를 측정한다.

로직 분석기로 PB6/PB7의 전이 간격과 펄스 폭을 확인하고 TIM4 계수, DIAG, CAN 결과를 대조한다. 짧은 지연은 펄스 수를 줄여도 누락 타임아웃에 도달하지 않을 수 있다. 기본 FEEDBACK_MISSING의 200 ms는 MCU에서 마지막으로 유효한 카운트가 변화한 때부터 센다. 한 채널 고착·잘못된 전이의 기대 고장 코드는 MCU 담당자와 정한다.

<!-- pagebreak -->

### 14.2 느린 상승·하강과 유효 전압 미달

**느린 전이**는 에지 사이의 간격을 유지하면서 각 에지의 전압이 올라가거나 내려가는 데 걸리는 시간을 늘리는 경우다. 가변 에지 신호 발생기나 외부 파형 지그로 상승·하강 시간을 조절하고 FPGA는 주입 트리거를 제공한다. 정상 주기와 진폭을 기준으로 잡은 뒤 상승 또는 하강 시간만 바꿔 어느 에지가 지연되거나 누락되는지 본다.

**전압 미달**은 HIGH의 최고 전압이 낮아지거나 LOW의 최저 전압이 높아지는 경우다. 가변 진폭·오프셋 발생기 또는 외부 DAC와 버퍼로 두 레벨을 설정한다. MUX 시험 입력에서 측정한 안정 구간 전압을 V_HIGH, V_LOW로 기록하고 부품의 VIH(min), VIL(max)와 비교한다.

| 변경 항목 | 시험 설정 | 관측 기준 |
|---|---|---|
| 느린 상승 또는 하강 | 정상 레벨·에지 간격에서 상승·하강 시간 중 하나를 변경 | 10~90% 상승 시간, 90~10% 하강 시간, MUX 전이 및 TIM4 계수 |
| HIGH 저하 | LOW 유지, V_HIGH를 낮춤 | V_HIGH가 VIH(min)보다 낮으면 HIGH 인식이 보장되지 않음 |
| LOW 상승 | HIGH 유지, V_LOW를 높임 | V_LOW가 VIL(max)보다 높으면 LOW 인식이 보장되지 않음 |

VIH(min)과 VIL(max)는 데이터시트의 논리 보장 한계다. 그 사이 전압에서 전이 시점과 검출 여부는 회로 조건에 따라 달라진다. 파형이 전원 레일에 닿지 않아도 논리 조건을 만족할 수 있다. MUX가 논리값으로 변환한 뒤에는 TIM4가 전이만 계수하므로, 전압 미달 자체를 진단할 때는 MUX 앞에 별도의 ADC나 비교기를 갖춘 측정 경로가 필요하다.

### 외부 주입 지그와 측정점

1. 선택 스위치나 점퍼로 FPGA 디지털 출력과 외부 전압원 중 하나만 MUX 시험 입력을 구동한다. 정상 파형과 이상 파형을 전환할 때 구동원이 겹치지 않는지 확인한다.
2. MUX의 A 시험 입력 3번과 출력 4번 또는 MCU PB6을 오실로스코프로 함께 본다. B는 입력 6번과 출력 7번 또는 PB7을 사용한다.
3. 실제 MUX 품번과 VCC에서 허용되는 입력 전압·전이 시간을 확인한다. 권장 전이 시간보다 느린 에지는 별도 벤치 지그에서 먼저 확인한다. 74HC157에서 느린 입력 전이는 출력 진동과 전류 증가를 일으킬 수 있다.

[TI SN74HC157 데이터시트](https://www.ti.com/lit/ds/symlink/sn74hc157.pdf) · [ST STM32F103RB 데이터시트](https://www.st.com/resource/en/datasheet/stm32f103rb.pdf)

### 14.3 Hi-Z와 부유 상태

**Hi-Z는 출력 드라이버를 끈 상태**다. FPGA 최상위 A/B 핀 각각에 OBUFT를 연결하면 T=0에서 0/1 값을 출력하고, T=1에서 해당 핀을 구동하지 않는다. 단선 시험은 A의 T만 1로 바꾸고 B를 정상 출력하는 방식으로 시작한다. 외부 아날로그 스위치로 신호선을 여는 방법도 가능하다.

현 지그의 10 kΩ 풀다운은 Hi-Z 상태의 MUX 시험 입력을 LOW 쪽으로 당긴다. A가 HIGH인 상태에서 Hi-Z로 바꾸면 방전 중 하강 에지가 한 번 생길 수 있다. 그 이후에는 MCU에서 A 고착 LOW와 같은 형태로 관측될 수 있으므로, 출력 차단 시각과 MCU가 본 마지막 에지를 각각 기록한다.

| 재현할 조건 | 지그 구성 | 기록할 값 |
|---|---|---|
| 풀다운이 있는 단선 | 기존 10 kΩ 유지, 선택한 FPGA 채널만 Hi-Z | 출력 차단 시각, 입력 방전, MCU 에지·계수 |
| 약하게 바이어스된 부유선 | 별도 지그에 높은 임피던스의 바이어스·누설 경로 구성 | 바이어스 전압·저항, 유지 시간, 프로브 연결 시 변화 |
| 레벨 저하 후 단선 | 외부 지그로 낮춘 HIGH를 인가한 뒤 구동 스위치를 엶 | 전압 저하와 구동 해제 시각, 실제 전압·MCU 반응 |

완전히 부유한 입력의 전압은 초기 전하, 누설, 노이즈, 프로브 영향에 따라 달라진다. 반복 시험은 별도 지그에서 약한 바이어스나 방전 경로를 정의하고, 실제 전압 범위와 지속 시간을 오실로스코프로 확인한다.

### 적용 조건과 기록

- FPGA 담당자는 채널·주입 시간·복귀 상태를 고정하고 실제 파형과 비교할 주입·복귀 시각을 기록한다.
- MCU 담당자는 MUX 출력과 TIM4 입력 필터·계수를 대조하고, 누락·추가 에지에 대한 기대 진단을 정한다.
- 같은 시험 회차에 실제 V_HIGH·V_LOW, 상승·하강 시간, 에지 간격, Hi-Z 유지 시간 중 해당 값을 기록한다. 주입 명령 시각과 입력의 실제 변화 시각을 DIAG·CAN 반응에 연결한다.

기본 수락은 NORMAL·NO_EDGE·GAP_500을 적용한다. 부유 상태와 한 채널 단선은 후속 전기 시험으로 둔다. 실제 신호선의 바이어스, MCU 감시 기준과 판정 근거를 확인한 뒤 별도 수락 항목을 정의한다.

[AMD UG953 OBUFT 진리표](https://docs.amd.com/r/2024.1-English/ug953-vivado-7series-libraries/OBUFT)

### 14.4 A 채널 주입 배선과 계측 연결

기존 A 채널의 1 kΩ 저항 앞에서 소스를 선택한다. **S1은 FPGA 쪽과 외부 발생기 쪽 중 한 곳을 연결하는 SPDT 스위치 또는 3핀 점퍼**다. 74HC157의 REAL/TEST 셀렉터와 별도이며, 배선을 바꾸거나 S1을 전환할 때는 두 출력을 비활성화한다.

![그림 14-1 A 채널 이상 주입기와 오실로스코프 연결](assets/fpga_spec_v1.2/injection_wiring.png)

| 연결점 | 배선 |
|---|---|
| S1의 FPGA 쪽 | Basys3 JA1. 에지 지연·누락 및 OBUFT Hi-Z 시험에 사용 |
| S1의 외부 쪽 | 발생기 CH1 OUT 또는 외부 DAC의 버퍼 출력. 진폭·전이 시간 조절에 사용 |
| S1 공통 단자 | 기존 1 kΩ → TP_A_IN → 74HC157 3번. 기존 10 kΩ은 TP_A_IN과 GND 사이에 유지 |
| MUX 출력·B 채널 | A는 4번 → PB6. B는 JA2 → 기존 1 kΩ → 6번, 7번 → PB7. 기존 B 풀다운 유지 |
| 오실로스코프 | CH1은 TP_A_IN, CH2는 TP_A_OUT(PB6). 여유 채널로 B(PB7)와 DIAG 또는 주입 마커 확인 |

**외부 발생기 동기화 예**로는 정상 1초와 이상 구간을 포함한 A 파형을 미리 만든다. 발생기를 외부 트리거 대기 상태로 두고, FPGA 시험 시작 마커로 A 재생과 FPGA B 출력을 맞춘다. 트리거 출력은 빈 GPIO와 발생기의 입력 레벨을 확인한 뒤 배정한다. ARM 이후 주입 전까지 PB6/PB7의 정상 위상과 MCU의 TEST_ACTIVE를 확인한다.

**전압 기준과 접지**는 기존 TEST 조건을 따른다. 모터 공급 OFF·PWM LOW를 확인하고, 발생기 리턴과 계측 기준을 제어부 신호 GND에 연결한다. 발생기의 부하 설정과 실제 부하를 맞추고 TP_A_IN에서 최저·최고 전압과 오버슈트를 직접 확인한다. 74HC157의 전원과 입력 허용 범위는 실제 장착품 기준을 적용한다. [Tektronix 발생기 부하 설정](https://www.tek.com/en/support/faqs/afg3000-output-load-selection-does-it-change-afg-output-impedance)

### 14.5 에지 지연과 아날로그 전압 이상에서 나오는 파형

![그림 14-2 정상 대비 에지 지연·느린 전이·전압 미달 예상 파형](assets/fpga_spec_v1.2/edge_and_level.png)

| 조건 | 그림에서 볼 점 | MCU에서 확인할 점 |
|---|---|---|
| 에지 지연 | 정상이라면 12.5 ms 후 바뀌는 상태를 25 ms 유지. 유지 구간의 다음 에지가 12.5 ms 늦어짐 | TP_A_OUT/PB6에서도 해당 에지가 늦어짐. A/B 상태 간격과 TIM4 계수를 비교 |
| 느린 상승·하강 | TP_A_IN의 상승·하강 구간이 길어짐. MUX가 인식하는 시점은 실측 | TP_A_OUT의 전이가 늦거나 반복될 수 있음. 추가·누락 에지와 TIM4 계수를 대조 |
| HIGH 저하·LOW 상승 | 그림의 낮은 HIGH와 높은 LOW는 VIL(max)와 VIH(min) 사이에 머묾 | MUX 출력에서 정상 전이가 나올 수도 있고, 늦거나 누락될 수도 있음. 실제 출력은 계측으로 확인 |

**에지 지연 시험**에서 A/B 전체 상태의 유지 시간을 늘리면 정상 순서를 보존할 수 있다. A만 지연하는 별도 시험은 B의 다음 에지와 순서가 뒤바뀔 수 있으므로 순서 이상을 별도 결과로 기록한다.

**느린 전이 시험**은 발생기와 오실로스코프로 먼저 파형을 확인한다. 느린 입력을 74HC157에 넣을 때는 데이터시트의 전이 시간 조건을 적용한다. 권장 조건 밖에서의 거동을 볼 때는 주 회로에서 분리한 동일 부품 지그에서 특성화하고, MUX 출력과 소비 전류를 먼저 확인한다. 그림의 전압과 기울기는 개념값이고, 실제 경계는 측정값으로 기록한다. [TI SN74HC157 데이터시트](https://www.ti.com/lit/ds/symlink/sn74hc157.pdf)

### 14.6 Hi-Z 단선과 약한 바이어스에서 나오는 파형

![그림 14-3 Hi-Z로 전환했을 때 풀다운과 약한 바이어스의 예상 파형](assets/fpga_spec_v1.2/high_impedance.png)

**기존 10 kΩ 풀다운으로 단선 모사.** S1을 FPGA 쪽에 두고 A가 HIGH인 시점에 JA1의 OBUFT T를 1로 올린다. JA2의 B 출력은 정상 출력을 유지한다. TP_A_IN은 선과 프로브의 정전용량 때문에 방전 곡선을 따라 LOW 쪽으로 내려간다. MUX가 LOW로 인식하면 PB6에 하강 에지가 한 번 나타날 수 있다. 주입 끝에 정상 구동을 재개할 때 생긴 전이는 복귀 에지로 기록한다.

**약한 바이어스로 부유선 모사.** 별도 A 입력 지그에서 기존 10 kΩ 풀다운을 분리하고, TP_A_IN에서 가변 기준 전압 V_BIAS까지 고저항 R_BIAS를 연결한다. JA1을 Hi-Z로 바꾸면 TP_A_IN은 보드·프로브의 정전용량, 입력 누설 및 저항의 영향을 받으며 V_BIAS 쪽으로 이동할 수 있다. 기존 10 kΩ을 함께 연결하면 그 저항과 R_BIAS가 분압을 만들어 최종 전압이 달라진다. V_BIAS와 R_BIAS는 실제 부하를 연결한 상태에서 정하고, 입력이 허용 범위에 있는지 확인한다.

**전압 미달 뒤 구동 해제.** S1을 외부 소스로 설정하고, 버퍼 출력과 S1 사이에 구동 해제용 직렬 아날로그 스위치를 둔다. 낮아진 HIGH를 먼저 인가한 뒤 스위치를 열어 Hi-Z를 재현한다. 발생기의 출력 OFF 동작은 모델별 회로가 다르므로, 선이 실제로 분리됐는지는 지그에서 확인한다.

| 함께 기록할 시점 | 출처 |
|---|---|
| 출력 구동을 끈 시점 | FPGA T 또는 직렬 스위치 제어 마커 |
| 전압이 내려가거나 바이어스 쪽으로 이동한 구간 | TP_A_IN 오실로스코프 파형 |
| MCU가 실제로 본 마지막 에지와 진단 응답 | PB6/PB7, TIM4, DIAG, CAN |

Hi-Z 동안의 전압과 MUX 전이는 지그 조건에 따라 달라진다. 그림의 하강 에지는 가능한 응답 예시다. [AMD UG953 OBUFT](https://docs.amd.com/r/2024.1-English/ug953-vivado-7series-libraries/OBUFT)

## 15 전동 시트 모터 시험 계획

시험 1·8은 실물 계측, 2는 보드 연동, 3~7은 FPGA 입력 시험이다. 시험 2~7은 모터 공급 OFF에서 진행한다. 시험별 파형은 15.6~15.10절, UART 시나리오 ID는 7절을 참조한다.

### 15.1 기동과 준비 시험

| 시험 | 방법 | 방식·난이도 | 판정 또는 기록 |
|---|---|---|---|
| 1 정상 기동 | 같은 6V 설정과 한 방향에서 기동·정상 회전·일반 STOP을 최소 3회 기록한다. 첫 PWM과 유효 A/B를 같은 시간축에 캡처한다. | 실물·중 | START_REAL 수락과 기동 시간, MCU tick·목표/실제 RPM·PWM·방향·운전 조건 및 유효한 공급 전압·전류를 저장한다. |
| 2 단절과 재접속 | 모터 공급 OFF에서 Qt TCP 단절과 CAN 단절을 각각 시험한다. 복구 전후의 Qt 요청, CAN 명령과 허가, 상태 및 PWM을 기록한다. | 보드 연동·중 | 허가 철회 또는 만료 후 PWM LOW를 확인한다. 현재 세션의 정지 상태를 확인하며, 이전 START 자동 전송이나 구동이 없어야 한다. |
| 3 기동 준비 지연 | Qt에서 ARM_TEST 수락 후 READY가 HIGH일 때 FPGA를 로컬 시작한다. FPGA 시작 후 약 1초간 A/B를 고정한 뒤 정상 펄스를 출력한다. | FPGA 주입·하 | 지연 중 TEST_ARMED를 유지한다. 정상 전이를 500 ms 연속 확인하고 ARM 수락 후 5초 이내에 TEST_ACTIVE에 진입한다. |
| 4 기동 준비 만료 | ARM 수락 이후 A/B 고정과, 정상 펄스 200 ms만 출력한 뒤 고정하는 입력을 각각 준다. | FPGA 주입·하 | TEST_ACTIVE에 진입하지 않는다. 5초 준비 만료 후 STOPPED, READY=0, PWM LOW와 새 epoch를 확인한다. |

시험 2는 새 Qt 연결의 heartbeat와 STM32의 최신 STOPPED 또는 FAULT를 확인한 뒤 허가를 회복한다. 정상 TEST 조건을 갖추면 Qt에서 새 시험 준비를 요청해 ARM_TEST 수락을 확인한다. 기본 제어 연동은 CAN 2.1 및 TCP can-do/1.1을 적용한다. 물리 START 누름 시험은 조작 MCU 확장 시 적용한다.

시험 3·4는 준비 상태를 검증하는 별도 FPGA 시험 설정을 사용한다. ARM 수락 시점과 실제 A/B를 기록한다. 시험 3에서 늦은 로컬 시작으로 시간 조건을 충족하지 못하면 회차를 다시 실행한다. 시험 4의 준비 만료는 별도 시험 결과로 기록한다.

### 15.2 이동과 정지 시험

| 시험 | 방법 | 방식·난이도 | 판정 또는 기록 |
|---|---|---|---|
| 5 NORMAL | 고정 20 cycle/s를 1초간 출력하고 2초 관측한다. END 이후 STOP까지 정상 A/B를 유지한다. | FPGA 주입·하 | TEST_ACTIVE 유지, CAN fault_mask=0, DIAG_FAULT=0. |
| 6 NO_EDGE | 동일한 1초 준비 뒤 A/B를 당시 레벨에 1초간 고정한다. | FPGA 주입·하 | FEEDBACK_MISSING, FAULT, 진단 GPIO 상승. 주입→GPIO 상승 300 ms 이내를 초기 기준으로 적용한다. |
| 7 GAP_500 | 동일한 준비 뒤 500 ms 고정하고 정상 A/B를 다시 출력한다. 복귀 상태로 500 ms 더 관측한 뒤 END를 보낸다. | FPGA 주입·중 | 시험 6과 같은 검출·시간 조건, 실제 A/B 복귀와 유효 END, END 후 새 CAN 상태·고장에서 래치 유지. |
| 8 실물 정지와 전원 차단 | 시험 1의 지그에서 일반 STOP과 물리 비상정지를 각각 수행한다. PWM과 A/B를 캡처하고 휠을 촬영한다. 비상정지는 VB+도 기록한다. | 실물·중 | 두 시험에서 PWM LOW와 축 정지를 확인한다. 비상정지는 VB+ 차단도 확인한다. 복구·재투입 후 새 START까지 구동을 억제한다. |

Jetson은 같은 회차의 CAN 기록을 대조해 주입·관측 전에 TEST_ACTIVE가 성립했는지 확인한다. TEST_READY는 TEST_ARMED에서도 HIGH다. 진입 근거가 없으면 INCONCLUSIVE로 기록한다. 초기 무펄스 기준 200 ms는 마지막 유효 카운트부터, 응답 한계 300 ms는 INJECT부터 잰다.

시험 7에서는 기대 고장으로 READY가 내려가도 A/B 복귀와 관측을 마친 뒤 END를 보낸다. END 후 500 ms 안에 같은 MCU 부팅·TEST 회차에서 새 MOTOR_STATE와 MOTOR_FAULT를 각각 받는다. 래치가 풀렸으면 FAIL, 복귀·END·새 보고의 근거가 부족하면 INCONCLUSIVE로 기록한다.

### 통합 순서

1. Qt 목업을 확인하고, 모터 공급 OFF에서 CAN 2.1 명령·허가 및 연결 복구를 확인한다.
2. 고정 펄스 3종의 CAN·GPIO·UART 판정을 검증한다. 준비 상태 시험 3·4는 별도 입력 설정으로 확인한다.
3. 같은 조건의 6V REAL 기록을 확보한다. 실측형 A/B를 적용하고 실물 보호 동작은 시험 8의 계측으로 확인한다.

### 15.3 실측 기반 FPGA 프로파일

고정 펄스 3종의 시나리오 버전은 fpga-basic/1.0이다. 실측형의 제안 버전은 fpga-profile/1.0이다. 처음 적용할 프로파일은 한 방향으로 제한한다.

| 구간 | FPGA 출력과 기록 |
|---|---|
| 고정 준비 | BASELINE_START부터 1초간 20 cycle/s를 출력한다. STM32는 연속 500 ms 동안 각 100 ms 구간에서 정방향 6~10 count(목표 8)를 확인한다. |
| 사전 재생 | 고정 준비 뒤 실측 A/B의 연속 회전 구간으로 전환한다. 유효한 피드백 구간과 재생 길이를 사전에 정하고, 전환 경계에서 A/B 위상 순서를 이어 간다. |
| 관측 또는 주입 | 설정한 오프셋에 도달하면 INJECT를 보내고 관측을 시작한다. NORMAL은 재생을 계속하고, NO_EDGE와 GAP_500은 그 시점의 A/B를 고정한다. |
| 복귀와 마감 | GAP_500은 500 ms 뒤 다음 정상 위상부터 다시 출력한 뒤 복귀 관측을 마치고 END를 보낸다. NORMAL은 END 뒤에도 STOP 또는 READY 해제까지 유효한 A/B를 이어 간다. |

로직 분석기로 취득한 A/B의 각 전이 시각과 위상에서 FPGA용 간격표를 만든다. 첫 실측 프로파일에 사용할 구간은 무부하 또는 저부하에서 연속 회전하는 구간으로 고른다. 기동 전과 정지 후의 0 RPM 구간은 REAL 기록에 보존한다. MCU의 TIM4 x4 계수로 출력축 1회전당 카운트 C를 맞춘다.

준비에서 사전 재생으로 넘어갈 때 추가·역방향 에지가 생기거나 정상 저속에서 무펄스 오탐이 생기는지 PB6/PB7 파형과 CAN으로 대조한다. 같은 원본에서 정상·유실 입력을 만들고, 재현 품질은 별도 실측 회차와 비교한다.

manifest에는 scenario_version, profile_id, source_operation_id, C, 실측 구간, 사전 재생 길이, 주입 오프셋, 시험 임계값과 펌웨어 빌드를 기록한다. 로컬 선택과 Jetson 판정 설정을 시험 전에 대조한다. FPGA UART는 7절의 기존 시나리오 ID와 프레임을 사용한다.

### 15.4 탁상 지그 제작과 계측

**구성.** FIT0482 모터, FIT0160 브래킷, FIT0085 휠 1개와 투명 커버 케이스를 사용한다. 속판 위에 모터와 휠만 고정한다. 제어보드·드라이버와 기존 비상정지 버튼은 케이스 밖에서 접근할 수 있게 둔다.

1. 모터 축과 휠이 맞는지 확인한다. 속판 위에 브래킷 위치를 표시하고, 소형 드릴을 빌려 체결 홀을 만든다. 속판과 브래킷은 나사·너트·와셔로 고정한다.
2. 지름 42 mm 휠은 반지름이 21 mm다. **속판에서 축 중심까지 약 24 mm 이상**을 조립 시작값으로 삼고 받침 높이를 정한다. 3D프린터로 작은 받침과 배선 클립을 제작한다. 전원 OFF에서 축을 손으로 한 바퀴 돌려 속판·뚜껑·배선과 간섭이 없는지 확인한다.
3. 휠에 표시선을 긋고, 배선은 보호 부싱과 클립으로 고정한다. 케이스를 책상에 고정하고 커버를 닫은 뒤 낮은 속도부터 시작한다. 조립 치수와 고정 상태는 현물에서 확인한다.

| 시험 | 신호와 계측 방법 |
|---|---|
| TEST 5~7 | 로직 분석기로 MUX 이후 PB6/PB7과 DIAG를 같이 캡처한다. 필요 시 READY도 관측한다. UART 시각·CAN 상태와 대조한다. |
| REAL 기동·일반 STOP | 로직 분석기로 드라이버 논리 입력 M1A/M1B와 MCU A/B를 함께 기록한다. 휴대폰 영상으로 실제 축 움직임을 확인한다. 영상과 캡처 시각을 동기화한 경우 축 정지 시간 계산에 사용한다. |
| REAL 비상정지 | 기존 U200의 공급 전압을 멀티미터의 MDD3A VB+–GND 실측과 대조한다. 차단 전후 VB+와 PWM·잔류 회전을 따로 기록한다. 빠른 전압 하강 시간을 확인할 때는 대여 오실로스코프를 사용한다. |

AN-1은 3.3V 논리 측정에 사용한다. 6V 전력점인 VB+에는 전압 계측기를 사용한다. 실물 운전 전 모터 STM32의 NC2 상태 입력과 CAN 보고, U200 공급 관측, 물리 차단 경로를 검증한다. TEST 진입 전에는 모터 공급 OFF와 PWM LOW를 확인한다.

### 15.7 정상 기동과 통신 복구의 관측

**시험 1 정상 기동.** MDD3A의 두 논리 PWM 입력과 MUX를 지난 엔코더 A/B를 같은 시간축에 캡처한다. 첫 구동 PWM 시각부터 MCU에 들어온 첫 유효 A/B 전이까지 시간을 기록한다. 휠의 움직임은 영상으로 대조한다. 가속할 때 A/B 전이 간격이 줄어드는 예시이며, 실제 간격은 6V REAL에서 확인한다.

![그림 15-1 실물 모터의 PWM과 엔코더 A/B 기동 예시](assets/fpga_spec_v1.3/real_start.png)

**시험 2 단절과 재접속.** 모터 공급 OFF에서 Qt TCP와 CAN을 각각 끊는다. Qt 단절 때는 Jetson의 허가 철회를, CAN 단절 때는 STM32의 유효 허가 만료를 기록한다. 연결이 돌아온 뒤 이전 START가 다시 송신되지 않고 M1A·M1B가 LOW를 유지하는지 확인한다. 다음 ARM_TEST는 새 Qt 조작으로 요청한다.

![그림 15-2 통신 단절과 복구 때 확인할 이벤트 및 PWM](assets/fpga_spec_v1.3/reconnect.png)

그림 15-2는 단절 전부터 PWM이 LOW인 조건을 보여준다. 이 경우 출력 차단 시간을 산출할 하강 에지가 없으므로, 허가·세션·START 재전송 여부와 PWM 유지 여부를 근거로 남긴다.

### 15.8 기동 준비용 FPGA 파형

**시험 3 기동 준비 지연.** ARM 수락과 READY HIGH 확인 후 FPGA를 로컬 시작한다. A/B를 00에 1,000 ms 유지하고 01부터 정상 순서로 전이한다. STM32가 정상 전이를 500 ms 연속 확인하여 ARM 수락 후 5초 안에 TEST_ACTIVE에 진입하는지 CAN으로 본다.

![그림 15-3 FPGA 시작 뒤 1초 정지 레벨과 정상 A/B 재개](assets/fpga_spec_v1.3/armed_delay.png)

**시험 4 기동 준비 만료.** A/B를 계속 00으로 고정하는 입력과, 20 cycle/s를 200 ms 동안 출력한 뒤 당시 레벨에 고정하는 입력을 각각 실행한다. 그림의 짧은 출력 예시는 00에서 시작하고, 200 ms에 예정된 다음 전이를 생략하여 A/B=10을 유지한다.

![그림 15-4 계속 고정과 200ms 정상 출력 뒤 고정](assets/fpga_spec_v1.3/armed_timeout.png)

1,000 ms와 200 ms는 FPGA 로컬 시작을 기준으로 한다. STM32의 5초 준비 마감은 ARM 수락이 기준이다. 시험 4는 TEST_ACTIVE 미진입, 만료 후 READY LOW·STOPPED·새 epoch를 확인한다. 시험 3·4는 별도 검증 설정으로 기록한다.

### 15.9 고정 펄스 기본 3종의 출력 시점

아래 시간은 FPGA 로컬 시작부터의 경과 시간이다. 정상 구간은 20 cycle/s, A/B 위상차 90°, 인접 전이 간격 12.5 ms다. 네 상태를 00 → 01 → 11 → 10 → 00 순서로 진행한다. 실제 MCU 방향 부호는 통합 때 대조한다.

![그림 15-5 NORMAL NO_EDGE GAP_500의 준비 주입 복귀 구간](assets/fpga_spec_v1.3/basic_cases.png)

| 시험 | FPGA 구현 경계와 관측 |
|---|---|
| 5 NORMAL | 1,000 ms에 INJECT로 관측 시작을 표시하고 A/B는 계속 전이한다. 3,000 ms에 END를 보낸 뒤에도 STOP까지 펄스를 유지한다. DIAG는 LOW를 유지한다. |
| 6 NO_EDGE | 1,000 ms에 예정된 전이를 생략하고 당시 A/B를 2,000 ms 관측 완료까지 유지한다. INJECT부터 첫 DIAG 상승까지의 초기 한계는 300 ms다. |
| 7 GAP_500 | 1,000~1,500 ms에 당시 레벨을 유지한다. 1,500 ms에 다음 정상 위상에서 재개하고 2,000 ms까지 관측한 뒤 END를 보낸다. END 후 새 CAN 보고에서 래치를 검증한다. |

그림 4-1~4-3에 각 A/B 전이 경계를 확대했다. 고정형 예에서는 NO_EDGE와 GAP_500이 A/B=10을 유지한다. GAP_500의 **고정 구간은 500 ms**, 마지막 정상 전이부터 첫 복귀 전이까지는 **512.5 ms**다. 실측형은 15.3절에 따라 고정 준비 뒤 사전 재생과 주입 오프셋을 적용한다.

### 15.10 실물 STOP과 비상정지의 계측 파형

**시험 8 정지·전원 차단.** M1A와 M1B, PB6과 PB7을 잡아 두 논리 PWM 입력이 모두 LOW가 되는 시점과 마지막 유효 A/B 전이를 기록한다. 영상에서 휠 정지를 확인한다. 실물 축 정지 시간을 계산하려면 캡처와 영상의 시각을 맞춘다.

![그림 15-6 일반 STOP과 비상정지 때 관측할 PWM A B VB+](assets/fpga_spec_v1.3/real_stop.png)

| 관측 | 기록 기준 |
|---|---|
| 일반 STOP | Qt STOP 이후 PWM LOW와 축 정지를 확인한다. 차단 뒤 추가 A/B 에지가 없으면 잔류 에지가 관측되지 않았다고 기록한다. |
| 물리 비상정지 | 비상정지 조작 이후 PWM LOW, VB+ 차단, 축 정지를 따로 기록한다. VB+는 전압 계측기를 사용한다. 차단 시간까지 확인하려면 오실로스코프로 기준 이벤트와 전압 하강을 함께 캡처한다. |
| 복구 | 비상정지 해제·전원 재투입 또는 연결 복구 뒤 새 START가 오기 전까지 PWM LOW를 확인한다. |

그림은 잔류 회전이 있는 예시다. A/B의 마지막 에지는 엔코더로 확인할 수 있는 마지막 움직임이며, 물리적 축 정지는 휠 영상으로 확인한다. VB+ 하강 모양과 각 시점의 순서는 실제 장치 조건에서 측정한다.
