# 개발 기록 작성법

개발 과정에서 해결한 문제와 판단 근거를 남깁니다. 발표나 포트폴리오를 만들 때 실제 변경과 검증 결과를 다시 찾을 수 있도록 관련 PR·이슈·커밋·시험 자료를 연결합니다.

- 기능 단위가 끝났거나, 문제의 원인을 찾았거나, 설계 결정을 내렸거나, 중요한 검증을 마쳤을 때 담당 폴더의 `HISTORY.md`에 기록합니다. 같은 작업의 기록은 해당 변경과 함께 PR에 올립니다.
- 새 항목은 위에 추가합니다. 이어지는 작업이 같은 문제라면 해당 항목에 새로 확인한 결과를 덧붙입니다. 여러 영역이 함께 해결한 문제는 주 담당 폴더 한 곳에 기록하고 참여자와 관련 링크를 남깁니다.
- 테스트 결과에는 목업·빌드·시뮬레이션·실물 계측 중 실제 확인한 환경과 결과를 적습니다. 검증을 수행하지 않은 작업은 `미실행`으로 표시하고, 후속 확인이 필요하면 한 문장으로 남깁니다. 작성 시점에 확인 가능한 링크를 쓰고 PR이 열린 뒤 필요하면 링크를 추가합니다.

## 공통 양식

```markdown
## YYYY-MM-DD · 작업 제목

- **담당·근거** — 이름 또는 GitHub ID, 관련 PR·이슈·커밋·검증 자료
- **문제** — 어떤 상황에서 무엇이 어려웠는지
- **판단과 변경** — 어떤 방법을 선택했고 왜 그렇게 결정했는지
- **검증** — 실제 확인한 환경·방법·결과, 필요한 후속 확인
```

AI에 맡길 때는 작업 폴더와 완료 범위, 코드만으로 알기 어려운 판단 이유나 시험 결과를 함께 전달합니다. AI가 작성한 기록은 실제 의도와 증거에 맞는지 담당자가 PR에서 확인합니다.
