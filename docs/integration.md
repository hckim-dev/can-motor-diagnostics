# 통합 순서

| 단계 | 합격 기준 |
| --- | --- |
| 1. Qt ↔ backend 목업 | 명령 처리 결과와 모터 상태를 각각 표시한다. 연결을 끊고 복구해도 이전 START가 재실행되지 않으며 실제 CAN 송신이 없다. |
| 2. 모터 6V 차단 상태에서 CAN·FPGA 연동 | STM32가 부팅 시 출력을 LOW로 유지한다. HELLO 버전, 현재 세션, 중복 명령, STOP 선점, 허가 소실 및 재접속 동작을 확인한다. FPGA의 정상 A/B와 MCU 입력의 일치를 확인한다. |
| 3. 고정 파형 시험 판정 | NORMAL, NO_EDGE, GAP_500에서 기대한 상태·고장·GPIO 응답 및 UART 증거를 대조한다. 필수 근거가 빠진 경우 판정 불가로 기록한다. |
| 4. REAL 실측 | 물리 차단 경로, NC2 관측 및 운전 한계를 확인하고 동일 설정에서 기동·회전·정지를 반복한다. PWM 억제, 공급 전압, 축 정지 시점을 각각 기록한다. |
| 5. 실측 파형 재생 | 프로파일과 시험 회차를 연결하고 실제 A/B 타이밍을 계측해 고정 파형 시험과 같은 증거 경로로 판정한다. |

각 담당자는 장비 통합 전에도 독립적으로 검증할 수 있습니다. Qt·backend는 목업으로, STM32는 CAN 입력 예제로, FPGA는 RTL 테스트벤치로 시작합니다. AI는 기본 제어와 시험 판정이 검증된 뒤 따로 진행합니다.

통합 결과에는 사용한 설정과 각 장치의 빌드를 기록합니다. 실제 판정에 쓴 소량의 재현 가능한 입력 예제는 저장소에서 공유하고, 계측 원본은 별도로 보관합니다. REAL의 STOP 이후 잔류 회전 샘플을 운전 회차에 연결하는 기준은 실측 전에 정합니다.
