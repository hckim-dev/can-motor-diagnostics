# Backend 개발 기록

의미 있는 작업을 마치면 [공통 양식](../docs/development-history.md)에 따라 기록합니다.

## 2026-11-20 · CAN 수신 복구와 누락 계측

- **담당·근거** — Codex · 설계서 v1.5 C3·C6·C10, [CAN 수신 회귀 시험](../tests/check_can_recovery.py)
- **문제** — CAN 단절 이후 통합 서비스를 다시 시작해야 했고, 커널 수신 큐 드롭과 측정 순번 공백을 기록에서 추적할 수 없었습니다.
- **판단과 변경** — 통합 서비스가 최대 세 차례 CAN 수신 소켓을 다시 엽니다. 호환 HELLO와 새 STATE로 수신 상태를 복구하고, 60초간 최신 상태가 연속 관측되면 시도 한도를 초기화합니다. 수신 점검과 통합 서비스에서 큐 드롭과 순번 공백을 기록합니다. 큐 드롭을 관측하면 진행 중인 시험을 판정 불가로 마감하고 REAL 운전과 샘플 수집 구간을 분리합니다.
- **검증** — Jetson Linux aarch64·Python 3.10.12에서 전체 141개 테스트를 경고를 오류로 처리해 통과했습니다. 가상 소켓과 부가 정보 주입으로 bus-off와 반복 단절, 실패 후 재연결, HELLO 이전 상태 거부, UART 지속 수신, 종료 중 재시도 취소, 드롭·순번 랩어라운드, 판정 경계와 리플레이를 검증했습니다. 실제 CAN 프레임 수신과 장치별 복구·누락 계측은 장비 미연결로 미실행입니다.
- **프레임 오류 재검토** — 본문이 잘린 CAN 프레임과 함께 들어온 유효한 큐 드롭 카운터도 버려졌습니다. 수신 점검과 통합 서비스가 드롭 수와 프레임 오류에 의한 단절을 같은 시각으로 기록하게 수정했습니다. 재연결 시 새 소켓 기준으로 계산하고, 리플레이에서 드롭 수를 재현하는 것을 확인했습니다. 경고를 오류로 처리한 전체 143개 테스트가 통과했습니다.
- **9a 최종 검증** — 전체 143개 테스트를 경고를 오류로 처리해 재실행했습니다. 별도 CLI로 순번 랩어라운드, 드롭, bus-off, 재시도 실패와 새 HELLO·STATE가 포함된 입력을 기록했습니다. 1배속과 빠른 리플레이에서 두 누락 지표, 측정값과 수집 구간, REAL 회차 및 원본 참조가 일치했습니다. 검토 범위에서 추가 코드 수정 사항은 발견하지 않았습니다. 실물 수신과 어댑터 복구 검증은 미실행입니다.
- **Backend 전수 회귀 검증** — 9a 변경을 포함한 작업 트리에서 전체 143개 테스트를 경고를 오류로 처리해 통과했습니다. 별도 CLI로 읽기 전용 TCP의 10Hz·재접속, 모의 CAN의 시험 준비·중복 요청·정지·이전 스트림 거부, FPGA UART의 hex·바이너리 수신을 확인했습니다. 세 시험 시나리오의 정상 결과와 래치 해제·중단·조기 EOF·REAL 기록 단절을 각각 기록하고 1배속·빠른 리플레이의 결과와 회차를 대조했습니다. 추가로 수정할 코드 결함은 발견하지 않았습니다.

## 2026-11-20 · TCP 통합 관측 서비스

- **담당·근거** — Codex · 설계서 v1.5 C0·C7·C10, [통합 실행 방법](README.md), [TCP 통합 시험](../tests/check_monitor.py)
- **문제** — TCP 목업과 CAN·UART 진단 기록이 별도 실행 경로여서 클라이언트가 같은 수집 세션의 상태와 판정을 확인할 수 없었습니다.
- **판단과 변경** — TCP 프레이밍을 공유하고, 예제 또는 장치 입력을 기존 진단 엔진·기록에 직렬로 전달하는 읽기 전용 서비스를 추가했습니다. TCP는 저장 지연 중에도 주기적으로 스냅샷을 보내며, 동기화한 판정만 기록과 동일한 이벤트 ID로 알립니다. 종료 시 관측 구간을 마감하고 새 입력 읽기를 중단합니다.
- **검증** — Jetson Linux aarch64·Python 3.10.12에서 전체 127개 테스트를 경고를 오류로 처리해 통과했습니다. TCP와 예제 입력의 판정·기록·리플레이, 모의 CAN bus-off와 가상 UART 분리, 클라이언트 재접속, 저장 지연·실패, 미완료 시험 중 종료와 연결 중 SIGTERM을 검증했습니다. 실물 CAN·UART는 미연결로 미실행입니다.
- **필드별 만료 재검토** — 처리 작업이 지연되면 TCP가 이미 만료된 `OP_PERMIT`와 측정값을 마지막 스냅샷에서 그대로 보낼 수 있었습니다. 수신 근거를 읽기 전용으로 전달하고 송신 시각에 공통 유효 기간 규칙을 적용합니다. 허가·전압·RPM·모터 상태의 서로 다른 만료 경계와 전체 128개 테스트가 통과했습니다.
- **종료 경계 재검토** — 수신 완료와 종료 요청이 겹치면 이미 읽은 장치 입력이 원본 기록에서 빠졌습니다. 종료 시 완료된 읽기는 기록하고 대기 중인 읽기는 취소하도록 수정했습니다. bus-off와 단절의 동시 기록, 버퍼 동기화 중 수신 완료, 대기 중인 예제의 취소를 검증했고 경고를 오류로 처리한 전체 130개 테스트를 통과했습니다.
- **Backend 최종 검증** — Jetson에서 경고를 오류로 처리한 전체 130개 테스트를 통과했습니다. 별도 Python 클라이언트로 기존 TCP 목업의 약 10Hz 전송과 재접속을 확인했습니다. 통합 CLI의 정상 시험, GAP 래치 해제, 조기 EOF에서 TCP 판정·이벤트 ID와 저장 기록을 대조하고 1배속·빠른 리플레이를 확인했습니다. 추가 코드 변경 사항은 발견하지 않았습니다. 실물 CAN·UART는 미연결로 미실행입니다.
- **커밋 전 호출부 재검토** — 공통 TCP 모듈로 이동한 `wait_for_stop`을 이전 위치에서 가져와 CAN 수신·제어 테스트 모듈이 로드되지 않았습니다. CAN 수신 테스트와 CAN 제어 목업이 공통 TCP 모듈에서 각자 필요한 함수를 직접 가져오도록 수정했습니다. 전체 130개 테스트와 별도 TCP 클라이언트 검증이 통과했습니다.

## 2026-11-20 · 6단계 포함 Backend 전수 검토

- **담당·근거** — Codex · 설계서 v1.5 C8·C10, [시험 판정과 리플레이 검증](../tests/check_diagnostics.py), [측정 기록 검증](../tests/check_measurement_recording.py)
- **문제** — `GAP_500` 종료 후 같은 모터 부팅에서 epoch가 바뀌어도, 새 epoch의 상태·고장 보고로 앞선 시험의 래치 유지를 확인해 `PASS`가 나왔습니다.
- **판단과 변경** — 주입 뒤 기대 고장을 처음 확인한 epoch를 보존합니다. 래치 유지 근거가 다른 epoch에서 왔다면 `INCONCLUSIVE / GAP_RECOVERY_EPOCH_CHANGED`로 기록합니다.
- **검증** — Jetson Linux aarch64·Python 3.10.12에서 경고를 오류로 처리한 전체 121개 테스트를 통과했습니다. 별도 프로세스로 읽기 전용 TCP의 초기 상태·10Hz·재접속, FPGA UART hex 입력, REAL 회차 기록과 1배속 재생, GAP epoch 변경 판정과 빠른 재생을 확인했습니다. 실물 CAN·UART는 미연결로 미실행입니다.
- **동일 시각 재검토** — `END`와 수신 시각이 같은 CAN 프레임이 입력 순서상 `END` 뒤에 있어도 복귀 근거에서 제외됐습니다. 공통 입력 순서에 따라 같은 시각의 `END` 앞뒤를 구분합니다. 입력 순서를 바꾼 두 사례와 전체 122개 테스트가 통과했습니다.
- **최종 검증** — Jetson에서 전체 122개 테스트를 경고를 오류로 처리해 재실행했습니다. 별도 TCP 클라이언트로 초기 상태·전송 주기·재접속을 확인했습니다. CLI로 세 시나리오의 정상 결과, 래치 해제, 강제 중단, 조기 EOF, REAL 기록 단절까지 일곱 사례를 기록·재생해 판정, 샘플, 회차 및 원본 참조를 대조했습니다. 검토 범위에서 추가 코드 변경 사항은 발견하지 않았습니다. 실물 CAN·UART 검증은 장비 미연결로 미실행입니다.

## 2026-11-20 · 측정값과 REAL 운전 회차 기록

- **담당·근거** — Codex · 설계서 v1.5 C10, [측정 기록 검증](../tests/check_measurement_recording.py), [모의 SocketCAN 검증](../tests/check_hardware.py)
- **문제** — 시험 원본과 판정은 저장했으나, 정규화한 측정값과 REAL 운전 관측 구간을 재현할 수 없었습니다.
- **판단과 변경** — 기존 CAN 결합기에서 완료·부분 샘플을 받아 `samples.csv`에 원본 증거와 함께 저장합니다. 수락된 모터 상태를 기준으로 `operations.jsonl`을 만들고, 관측이 끊어지면 다음 RUNNING 구간에 다른 UUID를 발급합니다. 기록·수집·리플레이가 같은 처리 경로를 사용하고, 새 파일도 증거 저장 확인과 완료 표시 전에 동기화합니다.
- **검증** — Jetson Linux aarch64·Python 3.10.12에서 경고를 오류로 처리한 전체 115개 테스트를 통과했습니다. 순서가 바뀐 샘플·결측·회차 경계, 모의 bus-off, 쓰기·동기화 실패를 검증했습니다. 합성 REAL 운전을 CLI로 기록한 뒤 1배속으로 재생해 값·회차 ID·증거 ID가 일치하는 것을 확인했습니다. 실물 CAN·UART는 미연결로 검증하지 않았습니다.
- **경계 재검토** — 새 모터 부팅을 알리는 프레임에서 이전 REAL 회차를 닫고, UART 시작 프레임에 순번 공백이 있으면 시험 ID를 붙이지 않습니다. 수집 종료 시각을 설정한 마감으로 제한하고 CAN 원본 행에 수신 인터페이스를 보존합니다. 네 조건을 회귀 시험으로 검증했고 경고를 오류로 처리한 전체 117개 테스트를 통과했습니다.
- **원본 부팅 번호 재검토** — 늦게 도착한 이전 부팅 프레임이 현재 부팅 번호로 기록됐고, HELLO보다 먼저 도착한 새 부팅의 시간 프레임에서는 번호가 빠졌습니다. 프레임에 명시된 부팅 번호나 epoch에서만 값을 읽도록 수정했습니다. 두 사례와 부팅 번호가 없는 프레임을 함께 검증했고 전체 118개 테스트를 경고를 오류로 처리해 통과했습니다.
- **기록 단절 재검토** — `recording_failed`가 입력에 남아 있어도 전후 REAL 운전과 부분 샘플을 이어 붙였습니다. 단절 이전 회차는 종료 미관측으로 닫고, 새 상태를 받을 때까지 회차 ID 없이 샘플을 기록합니다. 회귀 시험과 전체 119개 테스트를 경고를 오류로 처리해 통과했습니다.
- **기록 완료 재검토** — 수집을 시작한 뒤 종료 처리 없이 기록 컨텍스트를 닫으면 운전 회차가 빠진 상태로 완료 표시가 게시됐습니다. 종료 처리가 성공한 뒤에만 완료 표시를 게시하도록 수정했습니다. 조기 종료에서도 측정 파일은 남고 `manifest.json`은 생성되지 않음을 확인했으며, 경고를 오류로 처리한 전체 120개 테스트를 통과했습니다.

## 2026-11-20 · Jetson 실물 수신·송신 점검 경로

- **담당·근거** — Codex · 설계서 v1.5 C0·C2·C8, [Jetson 실행 방법](README.md), [장치 경로 시험](../tests/check_hardware.py)
- **문제** — 실제 CAN과 FPGA UART의 수신을 각각 확인하고, 모터 전원을 차단한 상태에서 CAN 송신 제출을 검증할 경로가 필요했습니다.
- **판단과 변경** — SocketCAN과 읽기 전용 115200 8N1 UART 입력을 기존 수신·기록 경로에 연결했습니다. Jetson 로컬 에코는 외부 CAN 수신에서 제외하고, bus-off를 단절로 기록합니다. 별도 송신 점검은 전원 차단 확인 후 `OP_HELLO` 한 프레임만 제출합니다.
- **검증** — Jetson Linux 5.15.199-tegra·Python 3.10.12에서 전체 103개 테스트를 경고를 오류로 처리해 통과했습니다. PTY 분할 수신·설정 복구, 모의 SocketCAN 수신·bus-off·재생, 실제 `can0` DOWN과 전원 확인 누락 거부를 확인했습니다. `can0`는 내장 mttcan이며 SLCAN 어댑터와 Basys3 tty가 열거되지 않아 실물 CAN·UART 수신과 실물 CAN 송신은 미실행입니다.
- **UART 점검 결과 재검토** — 정상 프레임 이후 순번이 역행해 수신기가 세션을 격리해도 수신 요약의 `ok`가 참으로 남았습니다. 격리 발생 횟수와 오류를 수신 요약에 남기고 점검 실패로 처리합니다. 정상 프레임, 역행 프레임, 격리 이후 프레임을 같은 입력으로 검증했고 전체 104개 테스트를 통과했습니다.
- **CAN 송신 점검 시간 검증** — 소켓이 처리할 수 없는 대기 시간을 설정하면 부팅 ID를 갱신하고 프레임을 제출한 뒤에 오류가 발생했습니다. 소켓 옵션을 제출 전에 검증하고 제출과 에코 대기에 같은 마감을 사용합니다. 가상 소켓에서 오류를 재현하고 부팅 ID 발급·송신 이전 거부를 검증했으며, 전체 105개 테스트를 통과했습니다.
- **동시 수신 마감 재검토** — 같은 selector 결과 중 첫 입력을 기록하는 동안 수집 마감이 지나면, 다음 장치의 단절이 뒤늦게 실패로 기록됐습니다. 장치별 읽기 직전과 오류를 기록하기 전에 마감을 확인합니다. CAN bus-off와 그에 따른 단절은 같은 관측 시각으로 기록하며, 경고를 오류로 처리한 전체 106개 테스트를 통과했습니다.

- **종결 검토** — Python 3.10에서 첫 스냅샷 이후 대기 시간이 지나면 연결이 끊기는 현상을 재현해 `asyncio.TimeoutError`를 처리하도록 수정했습니다. 검증 클라이언트는 전체 평균과 함께 스냅샷 사이의 송신 시각 차이도 확인합니다. 1초 지연 후 10개를 몰아 보낸 입력은 거부했고, 수정 후 Jetson에서 목업 6회와 접속·종료·프레이밍 검증을 통과했습니다. 쓰기 대기가 만료되면 연결 슬롯을 반환하는 동작은 모의 writer로 확인했습니다.
- **커밋 전 확인** — Python 3.10에서 기본 `TimeoutError`로는 비동기 타임아웃을 잡지 못하는 현상을 재현했습니다. `asyncio.TimeoutError`에 별칭을 붙여 두 예외를 구분했고, 개발 모드와 경고를 오류로 처리하는 설정으로 목업·재접속·종료를 다시 확인했습니다.
